## Outcome

The server and the browser work on `ess-ui/1`, and the canvas shows what ESS renders: the expanded
document, with the sections and overlays a page kind contributes and the bodies of widget
instances, each marked as inherited (epic decision D6). Findings carry ESS check ids on uilab
nodes. Placeholder reads show their rows, marked as samples when they are generated.

## Acceptance

`crates/uilab-app` is a binary crate, so its tests are unit tests in `crates/uilab-app/src/` (or
in a library target this story adds); widget tests are in `widget/src/lib/`.

- `serve_refuses_draft_format`: starting the server on a `ui-spec/1` file fails with ESS's message;
  at integration the coordinator runs `uilab serve --doc examples/library/library.ui.yaml` on a
  free port and records `GET /api/state` answering HTTP 200 with a document whose format is
  `ess-ui/1`.
- `outline_shows_inherited`: `OutlineNode` gains `inherited` (in `ess/domains/wire.yaml` first,
  then `task generate`); the outline of the library example's Loans page (`list_page`) holds the
  kind's `filters` section with `inherited: true`, and a widget instance holds its body nodes with
  `inherited: true`.
- `inherited_instruction_targets_author_node`: an instruction said with an inherited node selected
  is proposed against the nearest node the author wrote (the page for a kind's section, the widget
  instance for a body node); the test asserts the proposal's `target` path for both.
- `finding_carries_ess_check_id`: a document with an unknown widget yields a wire `Finding` whose
  `check` is `widget_expands` and whose `path` is the uilab path of the offending section.
- `placeholder_rows_from_fixture`: a section reading `{placeholder, fixture}` whose fixture file
  exists gets that file's rows.
- `placeholder_rows_generated`: the same section with a missing fixture file gets generated rows,
  each marked as a sample.
- `session_writes_ess_ui`: load the library example, then insert, replace, remove, undo and accept
  through the session; after every write the saved file passes `uilab_doc`'s re-exported
  `ess_ui_check::check` with 0 errors.
- Widget, one test per outcome:
  - `outline.inherited.test.ts`: an inherited outline node renders the inherited mark;
  - `canvas.inherited.test.ts`: the canvas's node list for the Loans page includes the inherited
    `filters` section, and for a widget instance its body nodes, each with the inherited class;
  - `canvasmode.inherited.test.ts`: the canvas offers no remove on an inherited node.
- `task check` exits 0.
